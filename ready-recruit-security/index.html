Introduction

Organisations that hold candidate and placement data have to show who can get in, from where, and what they did once inside. Ready Recruit answers that with a set of controls that are off by default and switched on per tenant. Once a control is on, the organisation's own administrators configure it under Admin → Security Settings.

🔐

Strong identity

Sign in through your organisation's identity provider (SAML SSO), or with a password plus a one-time code from an authenticator app.

🧱

Policy you control

Password length and complexity, lockout thresholds, session timeouts and confirmation-link expiry are all set by the organisation's own admins.

🌐

Network & file safety

Restrict access to approved IP ranges, scan every upload for viruses, and send email through your own mail gateway.

🧾

Accountability

User activity logs, sign-in tracking and an audit trail for bulk candidate exports show who did what, and when.

🔑Identity & access

Who can sign in, how they prove who they are, and how long a session can stay open.

🏢SAML Single Sign-On (SSO)

Users sign in with their organisation's existing identity provider instead of a separate Ready Recruit password. Joiners, leavers and password rules stay in one place, the corporate directory.

  • Admins connect the identity provider from a configuration page by entering its metadata (URL or XML) and IdP Entity ID.
  • X.509 certificates (public and private key) are stored per tenant to sign and verify SAML messages.
  • Users sign in from an SSO login link, and the identity provider's SAML response logs them straight in.

Configure in Admin → Security Settings → SAML SSO (Single Sign On)

📱Multi-Factor Authentication (MFA)

A second factor on top of the password: a time-based one-time code from an authenticator app on the user's phone. A stolen password alone no longer gets anyone in.

  • Each user sets up MFA from their Profile in two steps: install an authenticator app, then scan a QR code and enter the code to confirm.
  • Each user's MFA secret is encrypted at rest with a dedicated encryption key.
  • If a user loses their phone, an admin can turn off MFA for that user from the Users page so they can set it up again.

🔏Password policy

When the policy is on, every password has to meet a minimum length and complexity rules, and passwords expire on a fixed cycle.

  • Minimum length is set by the admin. It can't go below 8 characters and defaults to 14. The maximum is 72.
  • Complexity: at least one uppercase letter, one lowercase letter, one number and one symbol.
  • Expiry: passwords must be changed every 12 months.
  • Breached-password check: passwords that appear in known data breaches (the Have I Been Pwned database) are rejected with "This password has been previously exposed in N known data breaches."

🚫Account lockout policy

Stops password-guessing attacks. After a set number of failed sign-in attempts the account locks, either for a set time or until an admin unlocks it.

  • Threshold: 3, 5, 7 or 10 failed attempts, or never lock.
  • Duration: from 15 minutes up to 8 hours. The account unlocks on its own when the time is up.
  • Manual unlock: alternatively, locked accounts stay locked until an administrator unlocks them.

⏱️Session timeout & single active session

Inactive sessions end on their own, so a browser left open on a shared or unattended computer doesn't stay signed in.

  • Inactivity timeout from 15 minutes to 4 hours. The default is 1 hour.
  • One active session per user: signing in somewhere new ends the user's previous session.

Configure in Admin → Security Settings → Session Timeout Settings

✉️Account confirmation expiry

New users confirm their account from an emailed link. Admins decide how long that link stays valid, so old invitations can't be used to take over an account.

  • Set as a number and period. The default is 2 days.
  • The clock starts when the account is created or when the confirmation email is resent.

Configure in Admin → Security Settings → User Accounts Confirmation Expiry Time

🛡️Network & data protection

Where Ready Recruit can be reached from, what users agree to when they sign in, and how files and credentials are protected.

🌐Network settings: whitelisted IP addresses

Limit access to the organisation's own networks, such as offices and the corporate VPN. Requests from anywhere else get a 403 Forbidden page before any data loads.

  • Admins add one or more IP ranges, each with a "from" and a "to" address.
  • The check runs on every request, not only at sign-in.

📜Security responsibilities (logon banner)

A notice shown when users sign in, reminding them of their obligations: acceptable use, confidentiality, monitoring. It's a common requirement in government and enterprise security frameworks.

  • Written in a rich-text editor, so it can include headings, lists and links.
  • Each organisation writes its own wording.

Configure in Admin → Security Settings → Configure Security Responsibilities Banner

●Security Responsibilities Banner

Authorised use only. This system holds personal information. Activity is logged and monitored. By continuing you agree to the organisation's acceptable use and privacy policies.

Built-in data protection

🦠

Antivirus scanning

Every upload is virus-scanned when it lands in storage. Nobody can download an infected attachment or photo, except admins when the tenant explicitly allows it.

📮

Your own email gateway

Send system email through the organisation's own SMTP server (host, port, credentials, STARTTLS). The credentials are stored encrypted.

🔒

Encrypted secrets

MFA secrets and mail-server credentials are encrypted at rest. Passwords and one-time codes are removed from application logs.

🧰

Hardened platform

Strict HTTP security headers are set on every response, and dependencies with known vulnerabilities are patched routinely.

🧾Audit & compliance

Evidence for reviews, investigations and auditors: who signed in, what they did, and where data went.

📊User activity logs

Ready Recruit records user actions and saves them to each tenant's activity log in the background, in regular batches, so normal use doesn't slow down.

  • Users can see their own activity.
  • Roles with the "View all activity logs" permission can see everyone's.

👣

Sign-in tracking

For every user, Ready Recruit records how many times they've signed in, plus the time and IP address of their current and previous sign-ins.

📤

Bulk export audit trail

Every bulk export of candidate records is logged, so it's clear who took data out of the system, and when.

🗂️

Soft delete for attachments

Deleted attachments are kept rather than erased, so records can be recovered and reviewed later.
